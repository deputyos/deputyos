# deputyctl

Single management surface for an deputyOS appliance: lifecycle, profile
switching, model providers, doctor / limits, updates, backup, restore,
cost guardrails, quiet hours, and bounded resident-service repair.

`deputyctl` is the **operator-facing** binary of deputyOS. On a baked image
it lives at `/usr/local/bin/deputyctl` and is invoked directly (it is **not**
a systemd service — long-running daemons are the gateway services and
[deputypwa](deputypwa.md), not deputyctl). Most commands use synchronous I/O;
the integrated tunnel owns a small Tokio runtime so it can multiplex HTTP and
WebSocket streams for native agent UIs.

The command surface is the **frozen M0 surface** from
[`docs/02-profiles.md`](https://github.com/dipankarsr/deputyOS/blob/main/docs/02-profiles.md)
plus intentionally additive operator extensions such as `cost`,
`quiet-hours`, and `repair`.

!!! tip "Where to look first"
    - Operational quick-start: [operations/monitoring-and-logs.md](../../operations/monitoring-and-logs.md).
    - Profile concepts: [concepts/profile-class.md](../../concepts/profile-class.md).
    - Filesystem layout it reads/writes: [reference/system/filesystem-layout.md](../system/filesystem-layout.md).

## Synopsis

```
deputyctl [-v|-vv] <command> [command options]
```

## Global options

| Flag | Effect |
|---|---|
| `-v, --verbose` | Increase log level. `-v` = `debug`, `-vv` = `trace`. Counted; passing `-vvv` clamps at `trace`. Overrides the default `info` and is itself overridden by `RUST_LOG` if `RUST_LOG` is set. |
| `-h, --help` | Print top-level or per-subcommand help. Each `deputyctl <cmd> --help` page is autogenerated by clap from the same struct that drives dispatch. |
| `-V, --version` | Print the deputyctl crate version (clap-default; the richer info comes from [`deputyctl version`](#version)). |

## Logging

`deputyctl` uses [`tracing`](https://docs.rs/tracing) with `tracing-subscriber`
configured to write to **stderr** (never stdout — stdout is reserved for
machine-readable output such as `--json`). The default filter is `info`. Set
`RUST_LOG` to override:

```
RUST_LOG=deputyctl=debug,info deputyctl doctor
```

The verbose flag (`-v`, `-vv`) sets the default but loses to an explicit
`RUST_LOG`. Time and target are stripped from log lines so they remain
readable in journal output.

## Environment variables

`deputyctl` resolves every on-disk path through [`deputyctl/src/paths.rs`](https://github.com/dipankarsr/deputyOS/blob/main/deputyctl/src/paths.rs).
Each path has an environment override so the smoke harness and contributor
laptops can stage fixtures without root.

| Variable | Default | Purpose |
|---|---|---|
| `DEPUTYOS_PROFILES_DIR` | `/etc/deputyos/profiles` (else `./profiles`) | Directory of `*.toml` profile manifests. |
| `DEPUTYOS_ACTIVE_PROFILE_FILE` | `/etc/deputyos/active-profile` | One-line file naming the active profile id. Atomically rewritten by [`profile switch`](#profile-switch-id). |
| `DEPUTYOS_LIMITS_FILE` | `/etc/deputyos/limits.json` (else `deputyctl/etc/limits.qemu-aarch64.json`) | Per-device capability + limitation report. Read by [`limits`](#limits) and the [update](#update) target picker. |
| `DEPUTYOS_PROVIDERS_FILE` | `/etc/deputyos/providers.json` (else `deputyctl/etc/providers.json`) | Provider catalogue. Read by [`model list`](#model-list), [`model set`](#model-set), [`model test`](#model-test). |
| `DEPUTYOS_SECRETS_FILE` | `/etc/deputyos/secrets.env` | KEY=VALUE env file holding active provider credentials. Mode `0600`. |
| `DEPUTYOS_ACTIVE_PROVIDER_FILE` | `/etc/deputyos/active-provider` | One-line file naming the configured provider id. |
| `DEPUTYOS_RCLONE_CONFIG` | `/etc/deputyos/rclone.conf` | rclone config for [`backup`](#backup-now) / [`restore`](#restore-list). |
| `DEPUTYOS_BACKUP_CONFIG` | `/etc/deputyos/backup.toml` | Backup destination + retention. |
| `DEPUTYOS_BACKUP_RECOVERY_KEY_FILE` | `/etc/deputyos/backup-recovery-key` | Stable managed-backup encryption secret. |
| `DEPUTYOS_BACKUP_STATUS_FILE` | `/var/lib/deputyos/backup-status.json` | Last managed-backup result exposed by the resident agent. |
| `DEPUTYOS_HOOKS_DIR` | `/etc/deputyos/hooks.d` | Root of `pre-message/`, `post-message/`, `cost-alert/`, `update-applied/` hook script subdirs. |
| `DEPUTYOS_SYSTEMD_UNIT_DIR` | `/etc/systemd/system` | Where [`backup schedule`](#backup-schedule) writes the timer + service. |
| `DEPUTYOS_WIZARD_STATE_FILE` | `/var/lib/deputyos/wizard-state.json` | Cleared by [`factory-reset`](#factory-reset). |
| `DEPUTYOS_DEV_OUT` | unset | When set, all *invasive* writes (factory-reset, schedule, cost) are redirected under this dir; `systemctl daemon-reload` is skipped. The convention used by smoke tests on a contributor laptop. |
| `DEPUTYOS_COST_CONFIG` | `/etc/deputyos/cost.toml` | Cost + quiet-hours config. |
| `DEPUTYOS_COST_LEDGER` | `~/.<active_profile>/cost-ledger.jsonl` | Append-only JSONL ledger written by the agent profile. |
| `DEPUTYOS_COST_TRIPPED` | `/var/lib/deputyos/cost-tripped` | Marker that gates the active profile when caps trip. |
| `DEPUTYOS_COST_DEFAULTS` | `/etc/deputyos/cost-defaults.json` (else `deputyctl/etc/cost-defaults.json`) | Provider rate sheet for fallback cost estimation. |
| `DEPUTYOS_UPDATE_URL` | content of `/etc/deputyos/update-url`, else `file://./dist/manifest.json` | Manifest URL for [`update --check`](#update). |
| `DEPUTYOS_UPDATE_PUBKEY` | `/etc/deputyos/pubkey.minisign`, else `./dist/pubkey.minisign`, else `~/.config/deputyos/dev-keys/deputyos-dev.pub` | Public key that signs the manifest. |
| `DEPUTYOS_INSTALLED_VERSION` | content of `/etc/deputyos/version` | Reported by [`version`](#version) and consulted by `update --check`. |
| `DEPUTYOS_TARGET` | content of `limits.json`'s `target` field | Hardware target (e.g. `qemu-aarch64`). |
| `DEPUTYOS_ACTIVE_PROFILE` | content of `DEPUTYOS_ACTIVE_PROFILE_FILE` | Override for the [`update`](#update) artefact picker. |
| `DEPUTYOS_STAGING_DIR` | `/var/lib/deputyos/staging` | Where `update --apply` stages downloaded artefacts. |
| `DEPUTYOS_SLOTS_FILE` | `/var/lib/deputyos/slots.json` | A/B slot record consulted by [`rollback`](#rollback). |
| `DEPUTYOS_RELAY_SOCKET` | `/run/deputyos/relay.sock` | Default socket path for the hidden [`--internal-run-relay`](#internal-run-relay) flag. |
| `DEPUTYWIZARD_TOKEN_FILE` | `/run/deputyos/wizard.token` | Used by `deputyctl init` indirectly via the spawned [deputywizard](deputywizard.md). |
| `DEPUTYOS_CLOUDFLARED` | `cloudflared` | Override the cloudflared binary used by [`tunnel`](#tunnel). |
| `DEPUTYOS_CLOUDFLARED_PID` | `/run/deputyos/cloudflared.pid` | PID file written by `tunnel --background`. |
| `DEPUTYOS_RECONCILE_STATE` | `/var/lib/deputyos/reconcile-state.json` | Consecutive-failure counters for bounded repair. |
| `DEPUTYOS_RECONCILE_REPORT` | `/run/deputyos/reconcile.json` | Latest resident-service health and repair report. |

## Exit codes

deputyctl follows BSD `sysexits.h` conventions where they make sense and falls
back to traditional `0` / `1` everywhere else.

| Code | Meaning |
|---|---|
| `0` | Success. For doctor / status this also implies "no failing checks". |
| `1` | Runtime error. Network, signature, missing file, dependent process exited non-zero. The user-facing error is printed to stderr prefixed `deputyctl: error:`. |
| `64` | Usage error (`EX_USAGE`). Unknown subcommand, conflicting flags (e.g. both `--check` and `--apply` for `update`), missing required interactive input under non-TTY stdin, empty snapshot id. Scripts can probe this code to distinguish "you told me wrong" from "the world is broken". |

Individual subcommands document additional codes where they apply.

## Commands

### `repair`

Check the resident lifecycle agent, active profile and its HTTP health
endpoint, loopback terminal, and provisioned outbound tunnel.

```sh
deputyctl repair [--json] [--force]
```

The scheduled reconciler requires two consecutive failed probes before it
starts or restarts one of those compiled-in units. `--force` performs that
same allow-listed repair on the first failure. It cannot select arbitrary
systemd units or execute arbitrary commands.

### `init`

Run the first-boot wizard.

#### Synopsis

```
deputyctl init
```

#### Options

(none)

#### Behavior

1. Locate the [deputywizard](deputywizard.md) binary. Probes `PATH` first;
   then falls back to `target/debug/deputywizard` and `target/release/deputywizard`
   relative to the current directory so `cargo run -p deputyctl -- init` works
   in a dev tree.
2. Print the URL the user should open: `http://localhost:8088/wizard`.
3. Spawn `deputywizard serve --port 8088` and wait for it to exit.

This is the path used by support flows ("re-run the wizard after factory
reset"). On a baked image, the **first** boot runs `deputywizard.service`
directly via systemd (gated on `ConditionPathExists=!/var/lib/deputyos/wizard-state.json`);
`deputyctl init` is the manual re-run path.

#### Exit codes

- `0` — wizard exited cleanly.
- `1` — deputywizard binary not found, or wizard exited non-zero.

#### Related

- [deputywizard reference](deputywizard.md)
- [Wizard HTTP API](../apis/wizard-http.md)

### `profile list`

Show installed profiles + versions.

#### Synopsis

```
deputyctl profile list [--json]
```

#### Options

- `--json` — emit a JSON array of [`InstalledProfile`](#installed-profile-shape) objects.

#### Behavior

Enumerates `*.toml` files under `DEPUTYOS_PROFILES_DIR`, parses each manifest
through [`deputyctl/src/manifest.rs`](https://github.com/dipankarsr/deputyOS/blob/main/deputyctl/src/manifest.rs), and marks the active one (matched by id
against `DEPUTYOS_ACTIVE_PROFILE_FILE`'s contents) with a leading `*`.

A malformed manifest in the dir is a hard error — the image-rev contract
requires every shipped manifest to parse — so `profile list` exits `1` if any
file fails to load.

#### Examples

```
$ deputyctl profile list
* openclaw  OpenClaw   2026.4.27  stable
  hermes    Hermes     0.12.0     stable
  khoj      Khoj       2.1.0      beta
```

```
$ deputyctl profile list --json
[
  {
    "id": "openclaw",
    "display_name": "OpenClaw",
    "pinned_version": "2026.4.27",
    "release_channel": "stable",
    "manifest_path": "/etc/deputyos/profiles/openclaw.toml",
    "active": true
  },
  ...
]
```

#### Installed profile shape

```json
{
  "id": "string",                  // kebab-case, e.g. "openclaw"
  "display_name": "string",
  "pinned_version": "string",      // YYYY.M.D or semver
  "release_channel": "string",     // "stable" | "beta" | ...
  "manifest_path": "string",       // absolute path to the .toml
  "active": "bool"
}
```

#### Files read

- `DEPUTYOS_PROFILES_DIR/*.toml`
- `DEPUTYOS_ACTIVE_PROFILE_FILE`

#### Related

- [profile-toml schema](../schemas/profile-toml.md)
- [How to add a profile](../../how-to/add-a-profile.md)

### `profile status`

Detail on the active profile.

#### Synopsis

```
deputyctl profile status [--json]
```

#### Options

- `--json` — JSON output.

#### Behavior

1. Read the active profile id from `DEPUTYOS_ACTIVE_PROFILE_FILE`.
2. Load that profile's manifest.
3. Probe the systemd unit named in `[service].unit` via `systemctl is-active`.
4. Print id, display name, pinned version, install root, data dir, unit, and
   active state.

If no active profile exists (file missing or empty), prints `no active profile`
to stderr and exits `1`.

#### Examples

```
$ deputyctl profile status
id:              openclaw
display_name:    OpenClaw
pinned_version:  2026.4.27
install_root:    /opt/deputyos/profiles/openclaw
data_dir:        /home/agent/.openclaw
unit:            openclaw-gateway.service
active_state:    active
```

```json
{
  "id": "openclaw",
  "display_name": "OpenClaw",
  "pinned_version": "2026.4.27",
  "install_root": "/opt/deputyos/profiles/openclaw",
  "data_dir": "/home/agent/.openclaw",
  "unit": "openclaw-gateway.service",
  "active_state": "active"
}
```

#### Files read

- `DEPUTYOS_ACTIVE_PROFILE_FILE`
- The active profile manifest under `DEPUTYOS_PROFILES_DIR`.

### `profile switch <id>`

Atomic active-profile swap.

#### Synopsis

```
deputyctl profile switch <id> [--yes] [--dry-run]
```

#### Options

- `<id>` — profile id (e.g. `openclaw`, `hermes`, `khoj`). Must already be installed.
- `-y, --yes` — skip the interactive confirmation prompt. Required for non-TTY usage.
- `--dry-run` — print the planned actions and exit 0 without changes.

#### Behavior

The switch is implemented in
[`deputyctl/src/profile_switch.rs`](https://github.com/dipankarsr/deputyOS/blob/main/deputyctl/src/profile_switch.rs).
Per [`docs/02-profiles.md`](https://github.com/dipankarsr/deputyOS/blob/main/docs/02-profiles.md):

1. Validate the target profile id exists in `DEPUTYOS_PROFILES_DIR`.
2. If already active, print `already active: <id>` and exit 0.
3. If not `--yes` and not `--dry-run`, prompt `[y/N]` on the TTY. Refusing or
   non-TTY input aborts with exit 1.
4. Print the plan.
5. Stop the **current** profile's systemd unit (best effort).
6. **Atomic swap** of the active-profile pointer: write
   `<active-profile-file>.tmp` then `rename(2)` over the real path.
7. Reload AppArmor profile (best effort, via `apparmor_parser -r`).
8. Start the **new** profile's systemd unit (best effort).
9. Run every entry in `[upgrade].post_upgrade_hooks` through `sh -c`.
10. Print final unit state.

The swap is **committed** the moment step 6 completes — any subsequent
failure is logged as `warn:` but does not unwind. Recovery from a bad
post-hook is the user's job (`deputyctl doctor` to identify, `deputyctl
profile switch <old>` to revert).

!!! warning "Disruption"
    `profile switch` stops the current agent and starts a new one. In-flight
    chats on the old profile are dropped. There is no transparent migration of
    conversation state across profiles.

#### Examples

```
$ deputyctl profile switch hermes
plan:
  - stop unit for current profile "openclaw"
  - swap /etc/deputyos/active-profile -> "hermes"
  - reload AppArmor profile deputyos.hermes
  - start unit hermes-gateway.service
  - run post-upgrade hook: /opt/deputyos/profiles/hermes/post-upgrade.sh
switch profile "openclaw" -> "hermes"? [y/N] y
switched: openclaw -> hermes
unit:    hermes-gateway.service
state:   active
```

```
$ deputyctl profile switch khoj --dry-run
plan:
  - stop unit for current profile "openclaw"
  - swap /etc/deputyos/active-profile -> "khoj"
  - reload AppArmor profile deputyos.khoj
  - start unit khoj-gateway.service
(dry-run) no changes made
```

#### Exit codes

- `0` — switch completed (or already active, or dry-run).
- `1` — unknown id, user aborted, or non-TTY without `--yes`.

#### Files read / written

- Read: target manifest under `DEPUTYOS_PROFILES_DIR/<id>.toml`.
- Written: `DEPUTYOS_ACTIVE_PROFILE_FILE` (atomic rename).
- Side effects: `systemctl stop <old>`, `systemctl start <new>`, `apparmor_parser -r`.

#### Related

- [profile-toml schema](../schemas/profile-toml.md)
- [systemd-units](../system/systemd-units.md)
- [apparmor-profiles](../system/apparmor-profiles.md)

### `profile validate <paths>...`

Validate one or more profile manifests against the schema + invariants.

#### Synopsis

```
deputyctl profile validate <paths>... [--json]
```

#### Options

- `<paths>...` — one or more `.toml` paths. Globs are expanded by the shell.
- `--json` — emit a structured JSON report.

#### Behavior

For each path, runs the validator from
[`deputyctl/src/validate.rs`](https://github.com/dipankarsr/deputyOS/blob/main/deputyctl/src/validate.rs). Validation does **not** short-circuit on the first
error; every violation in every file is reported in one pass — so a CI run
surfaces all problems at once. Rules:

- `profile.id` must match `^[a-z][a-z0-9-]*$` and equal the file stem.
- `paths.install_root` must be absolute and start with `/opt/deputyos/profiles/<id>`.
- `paths.data_dir`, `paths.binary` must be absolute.
- `service.unit` must end with `.service`.
- `service.entrypoint` must be non-empty.
- `runtime.language` ∈ {`node`, `python`, `rust`, `go`, …}; `package_manager` consistent.
- `health.http_check` must be a URL.
- `health.startup_grace_s` > 0.
- `apparmor.profile` (if set) must be a valid identifier.
- `[[channels]]` entries must each declare `id`, `display_name`, `kind`.

#### Examples

```
$ deputyctl profile validate profiles/openclaw.toml profiles/hermes.toml
validated: 2/2
```

```
$ deputyctl profile validate /tmp/bad.toml
/tmp/bad.toml: profile.id: "Bad-ID" must match ^[a-z][a-z0-9-]*$ ...
/tmp/bad.toml: paths.install_root: must start with "/opt/deputyos/profiles/bad-id" ...
validated: 0/1
```

```json
{
  "results": [
    {
      "path": "profiles/openclaw.toml",
      "ok": true,
      "errors": []
    }
  ]
}
```

#### Exit codes

- `0` — every path validated cleanly.
- `1` — at least one file failed validation.

#### Related

- [profile-toml schema](../schemas/profile-toml.md)

### `up`, `down`, `restart`

Lifecycle controls for the active profile's systemd unit.

#### Synopsis

```
deputyctl up
deputyctl down
deputyctl restart
```

#### Behavior

1. Verify systemd is available (`systemd::available()` checks for `/run/systemd/system`).
2. Load the active profile's manifest.
3. Run `systemctl <verb> <unit>` where `<verb>` ∈ {`start`, `stop`, `restart`}
   and `<unit>` is the manifest's `[service].unit`.

#### Exit codes

- `0` — systemctl succeeded.
- `1` — systemd unavailable, no active profile, or systemctl exited non-zero.

#### Related

- [systemd-units](../system/systemd-units.md)

### `status`

Short health summary of the active profile.

#### Synopsis

```
deputyctl status
```

#### Behavior

Reads the active profile, queries `systemctl is-active`, runs the
"quick fail count" subset of doctor (no network, fast), and prints:

```
profile:  <id>
unit:     <unit>
state:    <active|inactive|failed|...>
doctor:   <N> failing check(s)
```

then prints the systemctl `status <unit>` block (truncated).

#### Exit codes

- `0` — unit is `active`.
- `1` — unit not active, systemd unavailable, or no active profile.

### `shell`

Drop into the profile's CLI.

#### Synopsis

```
deputyctl shell [--dry-run]
```

#### Options

- `--dry-run` — print the planned `exec` and exit without running.

#### Behavior

Loads the active profile manifest and `exec(2)`s the binary at
`paths.binary`, optionally with a per-profile sub-arg:

| Profile | Default sub-arg |
|---|---|
| `openclaw` | `repl` |
| `hermes` | `shell` |
| (other) | (none) |

Because `exec` replaces the process image, `ps` and `top` show the agent
binary directly — no `deputyctl` parent. If the binary is not present (typical
on a contributor laptop), exits **64** with a message that this requires a
baked image.

#### Exit codes

- `0` — `--dry-run` succeeded.
- `1` — `exec` itself failed (extremely rare).
- `64` — no active profile or binary missing.

### `doctor`

Full health check; nonzero on any failure.

#### Synopsis

```
deputyctl doctor [--json]
```

#### Options

- `--json` — emit a [`DoctorReport`](#doctor-json-shape) instead of the table.

#### Behavior

Runs the ordered list of checks defined in
[`deputyctl/src/doctor.rs`](https://github.com/dipankarsr/deputyOS/blob/main/deputyctl/src/doctor.rs)::`all_checks()`:

| Check | Expects |
|---|---|
| `active-profile-manifest` | active-profile points at a parseable manifest |
| `apparmor-enforcing` | AppArmor loaded with `deputyos.<profile>` in enforce |
| `ufw-default-deny` | `ufw status` reports default deny incoming + ufw active |
| `fail2ban-running` | fail2ban service is active |
| `clamav-healthy` | clamd active OR (per `limits.json`) RAM-tier disables clamd |
| `magika-present` | magika binary on PATH |
| `ssh-key-only` | sshd config: `PasswordAuthentication no`, `PermitRootLogin no` |
| `hardened-sysctls` | the deputyOS sysctl set is applied |
| `secrets-mode-0600` | `/etc/deputyos/secrets.env` mode is exactly `0600` |
| `agent-user-exists` | a user named `agent` is present |
| `zram-active` | `/dev/zram0` exists when `limits.json` requires it |
| ... | (full list in source — extending is `vec![Check {...}, ...]`) |

Each check returns one of `Pass`, `Warn(detail)`, `Fail(detail)`,
`Skip(detail)`. `Skip` is used on non-Linux dev hosts so `cargo test` works
on macOS — the production answer is "must be Linux".

#### Examples

```
$ deputyctl doctor
PASS  active-profile-manifest
PASS  apparmor-enforcing
FAIL  ufw-default-deny      ufw is inactive
        fix: sudo ufw default deny incoming && sudo ufw enable
PASS  fail2ban-running
SKIP  clamav-healthy        skipped on tier "lite" (clamd disabled by RAM)
...
3 fail / 1 warn / 18 pass / 2 skip
```

#### Doctor JSON shape

```json
{
  "linux": true,
  "checks": [
    {
      "name": "active-profile-manifest",
      "outcome": { "kind": "Pass" },
      "fix": "ensure /etc/deputyos/active-profile names an installed profile"
    },
    {
      "name": "ufw-default-deny",
      "outcome": { "kind": "Fail", "detail": "ufw is inactive" },
      "fix": "sudo ufw default deny incoming && sudo ufw enable"
    }
  ],
  "fails": 1,
  "warns": 0,
  "passes": 1,
  "skips": 0
}
```

#### Exit codes

- `0` — `fails == 0` (warns are tolerated by `doctor` itself; `make ci` may treat them differently).
- `1` — at least one Fail.

#### Related

- [security/default-on-controls](../../security/default-on-controls.md)
- [operations/monitoring-and-logs](../../operations/monitoring-and-logs.md)

### `limits`

Per-device capability + limitation report.

#### Synopsis

```
deputyctl limits [--json]
```

#### Options

- `--json` — emit the raw [`Limits`](#limits-json-shape) struct.

#### Behavior

Loads `DEPUTYOS_LIMITS_FILE` (defaults to `/etc/deputyos/limits.json`, which is
baked at image build time by the Lane B Ansible role) and renders it human-
readable per `docs/14-limitations.md`:

```
Device:   rpi5-8gb (8192 MB RAM, sd-card storage)
Tier:     standard

What this device CAN do:
  ✓ Run a local LLM
  ✓ Voice wake-word
  ✓ On-demand virus scan via Magika + clamscan
  ✓ Heavy channels available: voice, vision

What this device CANNOT do (and why):
  ✗ background-large-models (RAM tier insufficient for >7B param models persistently)
       Unblock: switch to rpi5-16gb or x86 mini-PC

  Channels disabled by RAM tier: video-call

Currently active warnings:
  (none)

Run `deputyctl doctor` for live pressure metrics.
```

#### Limits JSON shape

```json
{
  "target": "rpi5-8gb",
  "tier": "standard",
  "ram_mb": 8192,
  "ram_class": "8GB",
  "storage_class": "sd-card",
  "capabilities": {
    "local_llm": true,
```

### `model set`

Interactive provider/model picker.

#### Synopsis

```
deputyctl model set [--provider <id>] [--key-from-stdin] [-y|--yes]
```

#### Options

- `--provider <id>` — skip the picker prompt; jump straight to entering a key.
- `--key-from-stdin` — read the key from stdin instead of prompting on TTY (required for piping).
- `-y, --yes` — skip the confirmation prompt.

#### Behavior

1. If `--provider` is unset and stdin is a TTY: print the catalogue, prompt
   for a number. Empty input or invalid number aborts.
2. If `--provider` is unset and stdin is **not** a TTY: exit `64` (you must
   pass `--provider`).
3. Resolve the key:
   - `--key-from-stdin` → read one line from stdin.
   - TTY → masked prompt via [`rpassword`](https://docs.rs/rpassword).
   - non-TTY without `--key-from-stdin` → exit `64`.
4. Empty key → exit `1`.
5. Confirm `[y/N]` unless `--yes`.
6. **Atomic write** of the key into `DEPUTYOS_SECRETS_FILE`. Existing keys for
   other providers are preserved; the line for the target env var is replaced
   in place if present, appended if absent. The temp file is created with
   mode `0600` before the rename.
7. **Atomic write** of the provider id into `DEPUTYOS_ACTIVE_PROVIDER_FILE`.

#### Examples

```
$ deputyctl model set
available providers:
   1. openrouter             OpenRouter (OPENROUTER_API_KEY)
   2. openai                 OpenAI (OPENAI_API_KEY)
   ...
pick a number (or blank to abort): 1
enter key for OpenRouter (OPENROUTER_API_KEY): ********
set provider "openrouter" with OPENROUTER_API_KEY key (length 73)? [y/N] y
configured: provider=openrouter key_env=OPENROUTER_API_KEY (run `deputyctl model test` to round-trip)
```

```
$ printf '%s' "$OPENROUTER_API_KEY" | deputyctl model set --provider openrouter --key-from-stdin --yes
configured: provider=openrouter key_env=OPENROUTER_API_KEY (run `deputyctl model test` to round-trip)
```

#### Exit codes

- `0` — wrote the secret + active-provider pointer.
- `1` — empty key, user aborted, or write failed.
- `64` — unknown provider id, or non-TTY without `--provider` / `--key-from-stdin`.

#### Files read / written

- Read: `DEPUTYOS_PROVIDERS_FILE`, existing `DEPUTYOS_SECRETS_FILE`.
- Written: `DEPUTYOS_SECRETS_FILE` (mode 0600), `DEPUTYOS_ACTIVE_PROVIDER_FILE`.

### `update`

Update client.

#### Synopsis

```
deputyctl update --check [--json]
deputyctl update --apply [-y|--yes] [--json]
```

#### Options

- `--check` — read the signed manifest from CDN and report what would change.
- `--apply` — apply an update (A/B swap with watchdog rollback in M6; today, stage to `DEPUTYOS_STAGING_DIR`).
- `-y, --yes` — skip the `--apply` confirmation prompt.
- `--json` — structured JSON output.

`--check` and `--apply` are **mutually exclusive**. Passing both — or neither —
exits `64`.

#### Behavior (--check)

1. Resolve the manifest URL with the documented precedence:
   1. `DEPUTYOS_UPDATE_URL`
   2. `/etc/deputyos/update-url`
   3. dev fallback `file://./dist/manifest.json`
2. Resolve the public key:
   1. `DEPUTYOS_UPDATE_PUBKEY`
   2. `/etc/deputyos/pubkey.minisign`
   3. `./dist/pubkey.minisign`
   4. `~/.config/deputyos/dev-keys/deputyos-dev.pub`
3. Fetch manifest, fetch sidecar `<url>.minisig`, verify with `minisign -V`.
4. Read installed version, current target (from `limits.json`), active profile.
5. Pick the manifest's first artefact whose `target` and `profile` match.
6. Compare `manifest.release_version` to installed; report `update_available`.

#### Behavior (--apply)

Steps 1-5 from `--check`, then:

6. If `release_version <= installed`, print "already up to date" and exit 0.
7. Confirm `[y/N]` unless `--yes`.
8. Resolve URLs against the manifest origin (`url` field, else `filename`).
9. Download artefact + `.minisig` to `DEPUTYOS_STAGING_DIR`.
10. Verify SHA256 against `artefact.sha256`.
11. Verify minisign signature against the same pubkey.
12. Fire `update-applied` hooks (best effort).
13. Print "staged at <path>" — actual A/B swap is M6.

!!! warning "M6 status"
    Today, `update --apply` ends at "staged" with a clear pointer to
    `docs/08-update-rollback.md`. The integrity guarantees (SHA + minisign) are
    real; the bootloader swap is not yet wired.

#### Examples

```
$ deputyctl update --check
manifest:    https://cdn.deputyos.com/dev/manifest.json
channel:     dev
installed:   2026.4.20
latest:      2026.4.27
status:      update available
target:      qemu-aarch64
profile:     openclaw
artefact:    deputyos-openclaw-qemu-aarch64-2026.4.27.qcow2 (qcow2)
size:        1873294848 bytes
sha256:      9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08
```

```json
{
  "ok": true,
  "installed_version": "2026.4.20",
  "latest_version": "2026.4.27",
  "channel": "dev",
  "update_available": true,
  "target": "qemu-aarch64",
  "profile": "openclaw",
  "matching_artefact": { ... },
  "manifest_origin": "https://cdn.deputyos.com/dev/manifest.json"
}
```

#### Exit codes

- `0` — up to date, or check completed, or apply staged.
- `1` — verification failed, fetch failed, no matching artefact, user aborted.
- `64` — `--check` and `--apply` both passed, or neither passed.

#### Files read / written

- Read: `update-url`, `pubkey.minisign`, `version`, `active-profile`, `limits.json`.
- Written: under `DEPUTYOS_STAGING_DIR` (`apply` only).

### `rollback`

Force boot into the inactive A/B slot on next reboot.

#### Synopsis

```
deputyctl rollback
```

#### Behavior

1. Read `DEPUTYOS_SLOTS_FILE` (`/var/lib/deputyos/slots.json`).
2. Validate the JSON shape and the recorded SHA256 of the inactive slot's
   image (real cryptographic check — corrupted rollback target caught here,
   not after reboot).
3. Refuse to perform the swap, print which slot/version would be active,
   and exit **64** with a clear "lands in M6" message.

The integrity check is real and load-bearing for the M2/M4 contract. M6's
swap implementation will layer on top without changing this validation
logic.

#### Slots file shape

```json
{
  "active": "A",
  "inactive": "B",
  "version_a": "2026.4.27",
  "version_b": "2026.4.20",
  "inactive_sha256": "9f86d081...",
  "inactive_image_path": "/var/lib/deputyos/slot-b.img"
}
```

#### Examples

```
$ deputyctl rollback
rollback: inactive slot integrity verified (9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08)
rollback: would roll back from slot A to slot B (version 2026.4.20)
rollback: A/B swap implementation lands in M6 — see docs/08-update-rollback.md
```

#### Exit codes

- `0` — never (today). M6 will return 0 on success.
- `64` — rollback target not provisioned, or M6 not yet shipped.
- (anyhow error) — slots.json malformed, or integrity check failed.

### `backup now`

#### Synopsis

```
deputyctl backup now [--dry-run] [--to-cloud]
```

#### Options

- `--dry-run` — pass `--dry-run` to rclone.
- `--to-cloud` — create a quiesced schema-v3 bundle, encrypt it with the

#### Behavior

1. Verify `rclone` is on PATH.
2. Load `DEPUTYOS_BACKUP_CONFIG` (TOML; `[backup].remote` required).

### `backup schedule`

Configure a cron-like schedule.

#### Synopsis

```
deputyctl backup schedule [--every <interval>] [--at <HH:MM>] [--to-cloud] [--list] [--disable]
```

#### Options

- `--every <interval>` — `6h`, `30m`, `1d`. Default if neither `--every` nor `--at`: `--every 6h`.
- `--at <HH:MM>` — daily at this local time. Mutually exclusive with `--every`.
- `--to-cloud` — make the generated service run `backup now --to-cloud`.
- `--list` — print the current schedule's `OnCalendar=` line.
- `--disable` — stop and remove the timer.

#### Behavior

Writes `deputyos-backup.timer` and `deputyos-backup.service` under
`DEPUTYOS_SYSTEMD_UNIT_DIR`, then runs `systemctl daemon-reload` +
`systemctl enable --now deputyos-backup.timer`. The service simply runs
`deputyctl backup now` (path inferred from `current_exe`).

In dev mode (`DEPUTYOS_DEV_OUT=<dir>`), units are written under
`<dev-out>/systemd/` and `systemctl` is **not** invoked, so a contributor
laptop never installs system-wide units.

`--every`-to-`OnCalendar` mapping:

| `--every` | `OnCalendar=` |
|---|---|
| `6h` | `*-*-* 00/6:00:00` |
| `30m` | `*:0/30:00` |
| `1d` | `*-*-* 03:00:00` |

#### Examples

```
$ deputyctl backup schedule --every 6h
backup schedule: wrote /etc/systemd/system/deputyos-backup.timer
backup schedule: wrote /etc/systemd/system/deputyos-backup.service
scheduled: OnCalendar=*-*-* 00/6:00:00
```

```
$ deputyctl backup schedule --list
OnCalendar: *-*-* 00/6:00:00
```

```
$ deputyctl backup schedule --disable
backup schedule: removed /etc/systemd/system/deputyos-backup.timer
backup schedule: removed /etc/systemd/system/deputyos-backup.service
disabled
```

#### Exit codes

- `0` — schedule wrote / disabled / listed.
- `1` (anyhow) — `--every` and `--at` both passed, bad interval, or write failed.

#### Files written

- `DEPUTYOS_SYSTEMD_UNIT_DIR/deputyos-backup.timer`
- `DEPUTYOS_SYSTEMD_UNIT_DIR/deputyos-backup.service`

### `restore snapshot`

Atomic restore from a snapshot id.

#### Synopsis

```
deputyctl restore snapshot --snapshot <id> [-y|--yes]
```

#### Options

- `--snapshot <id>` — id from `restore list`.
- `-y, --yes` — skip confirmation.

#### Behavior

1. Stop the active profile's unit (best effort).
2. Move the current `data_dir` aside to `<data_dir>.pre-restore-<epoch>`.
3. `rclone copy <remote>/<host>/<id>/ <data_dir>`.
4. **Roll back** the move-aside if rclone fails.
5. Start the active profile's unit.

The rollback path is real — it's why the move-aside happens before the
copy. On a successful restore the `.pre-restore-*` dir is left in place
(disk insurance) for the user to delete manually.

!!! warning "Destructive"
    `restore snapshot` replaces the entire `data_dir`. This includes all
    conversations, learned skills, and per-profile state. The `.pre-restore-*`
    sidecar is your only undo button; it's not auto-cleaned.

#### Examples

```

... rclone copy progress ...
restored: snapshot myhost-1713964800T-utc into /home/agent/.openclaw (rollback copy at /home/agent/.openclaw.pre-restore-1714137600)
```

#### Exit codes

- `0` — restore succeeded.
- `1` — rclone missing, copy failed (rolled back), user aborted.
- `64` — empty snapshot id.

```json
  "tripped": false,
  "on_cap_trip": "pause",
  "warn_at_pct": 80,
  "ledger_path": "/home/agent/.openclaw/cost-ledger.jsonl",
  "config_path": "/etc/deputyos/cost.toml",
  "recent_expensive": [ ... up to 5 LedgerEntry objects ... ]
}
```

#### `cost set`

Updates `cost.toml` (atomic, mode `0600`). All flags are optional but at
least one must be passed (else exit `64`). `on_cap_trip` must be one of
`pause`, `warn`, `nothing`. `warn_at_pct` must be 0..=100. Negative caps
are rejected.

```
$ deputyctl cost set --daily-cap 10 --monthly-cap 200 --on-cap-trip pause --warn-at-pct 90
daily_cap_usd:    $10.00
monthly_cap_usd:  $200.00
on_cap_trip:      pause
warn_at_pct:      90%
wrote:            /etc/deputyos/cost.toml
```

#### `cost reset`

Clears the tripped marker file (`DEPUTYOS_COST_TRIPPED`, default
`/var/lib/deputyos/cost-tripped`). **Does not** touch the ledger.
Idempotent.

#### `cost ledger [--last N]`

Reads `DEPUTYOS_COST_LEDGER` (a JSONL file the agent profile writes), sorts
by timestamp descending, prints the last N (default 20). With `--json`,
emits the array.

#### Ledger entry schema

```json
{
  "timestamp": "2026-04-26T12:34:56Z",   // RFC3339 UTC
  "provider": "openrouter",
  "model": "anthropic/claude-3.5-sonnet",
  "input_tokens": 1234,
  "output_tokens": 567,
  "cost_usd": 0.0123,
  "request_id": "req_abc123"
}
```

The agent profile is the **producer** of these entries. deputyctl is
read-only on the ledger (except for `cost reset`, which only clears the
marker). Missing `cost_usd` can be filled by the consumer using
`DEPUTYOS_COST_DEFAULTS` rate sheets.

#### Cap evaluation

- **Daily** — sum `cost_usd` of entries whose `timestamp` starts with
  today's `YYYY-MM-DD` (UTC). Compare to `caps.daily_usd`.
- **Monthly** — sum `cost_usd` of entries whose `timestamp` starts with
  `YYYY-MM` (UTC). Compare to `caps.monthly_usd`.
- A cap of `0.0` means "disabled".
- States: `Ok` < `caps.warn_at_pct%` of cap; `Warn` between `warn_at_pct`
  and 100; `Tripped` ≥ 100%.

When a `Tripped` state is observed, deputyctl fires the
`CostAlert` hook (see [hook-payloads schema](../schemas/hook-payloads.md)) (level=`trip`)
and — if `on_cap_trip == "pause"` — writes the tripped marker and runs
`systemctl stop` on the active unit (best effort; in dev mode the systemctl
call is skipped).

#### Examples

```
$ deputyctl cost
today:         $1.2340 / $5.00     (25% — ok)
month:         $12.3450 / $100.00  (12% — ok)
on_cap_trip:   pause
warn_at_pct:   80%
tripped:       false

recent (top 5 by cost):
  $ 0.0820  2026-04-26T12:34:56Z  openrouter      anthropic/claude-3.5-sonnet
  ...
```

```
$ deputyctl cost --check
$ echo $?
0
```

#### Exit codes

- `0` — summary, set, reset, ledger ok, or `--check` reports not tripped.
- `1` — `--check` reports tripped, or write failed.
- `64` — `cost set` with no fields changed.

### `quiet-hours`

Quiet-hours schedule: when to pause / refuse messages.

!!! note "Surface extension"
    See note under [`cost`](#cost) — same authorisation, same `cost.toml` config file.

#### Synopsis

```
deputyctl quiet-hours [--json]
deputyctl quiet-hours set [--start <HH:MM>] [--end <HH:MM>] [--enable] [--disable] [--behaviour <pause|refuse|nothing>]
```

#### Default invocation

`deputyctl quiet-hours` shows the current schedule + whether it's active
right now:

```
enabled:     true
start:       22:00 (local)
end:         07:00 (local)
behaviour:   pause
active_now:  false
config:      /etc/deputyos/cost.toml
```

```json
{
  "enabled": true,
  "start": "22:00",
  "end": "07:00",
  "behaviour": "pause",
  "active_now": false,
  "config_path": "/etc/deputyos/cost.toml"
}
```

#### `quiet-hours set`

Updates the `[quiet_hours]` section of `cost.toml` (atomic, mode `0600`).
At least one of `--start`, `--end`, `--enable`, `--disable`, `--behaviour`
must be passed (else exit `64`). `--enable` and `--disable` are mutually
exclusive. `--behaviour` ∈ {`pause`, `refuse`, `nothing`}. Times are `HH:MM`
in **local time** (24-hour).

#### Time semantics

- The window is closed-open `[start, end)`. `start == end` is treated as
  empty (24-hour silence is not what the user means; they'd disable instead).
- Cross-midnight windows are supported: if `start > end`, the window is
  `[start, 1440) ∪ [0, end)`.
- "Local time" resolves via `TZ` env (`UTC`, `+05:30`, `-0800`, etc.) →
  `/etc/timezone` → `date +%z` → UTC. DST is honoured to the extent the
  system's `date` command honours it.

#### Examples

```
$ deputyctl quiet-hours set --start 22:00 --end 07:00 --enable --behaviour pause
enabled:     true
start:       22:00
end:         07:00
behaviour:   pause
wrote:       /etc/deputyos/cost.toml
```

```
$ deputyctl quiet-hours set --disable
enabled:     false
...
```

#### Exit codes

- `0` — show / set ok.
- `64` — `--enable` and `--disable` both passed, or no fields changed.

- [operations/cost-guardrails](../../operations/cost-guardrails.md) (same config file)

### `--internal-run-relay` <a id="internal-run-relay"></a>

!!! warning "Internal — not part of the public surface"
    `--internal-run-relay <SOCKET>` is a hidden top-level flag, intentionally
    omitted from `--help` and from the frozen subcommand surface in
    `docs/02-profiles.md`. It exists so the systemd unit fronting the
    [message relay](../apis/message-relay.md) can run deputyctl as the relay
    server. Documented here for transparency; do not script against it.

#### Synopsis

```
deputyctl --internal-run-relay <SOCKET-PATH>
```

#### Behavior

1. Initialize tracing.
2. Bind a `SOCK_STREAM` Unix-domain socket at `<SOCKET-PATH>` (or
   `DEPUTYOS_RELAY_SOCKET` if no path is supplied; default
   `/run/deputyos/relay.sock`). Mode `0600`.
3. Accept connections one-at-a-time. Each connection is one newline-delimited
   JSON request:
   ```json
   { "kind": "pre-message" | "post-message" | "cost-alert" | "update-applied",
     "payload": { ... } }
   ```
4. Dispatch to `crate::hooks::fire_hook_in_collect` against `DEPUTYOS_HOOKS_DIR`.
5. Reply with one JSON line:
   ```json
   { "ok": true|false, "errors": [{"script": "...", "code": 0, "stderr_tail": "..."}, ...] }
   ```
6. Close the connection. Loop forever.

The argv-scan happens **before** clap parses, so this flag is not visible
to `--help` and does not appear in the [`Command`] enum.

#### Files read / written

- Read: `DEPUTYOS_HOOKS_DIR/<kind>/*` executable scripts.
- Written: socket file at the supplied path (mode `0600`).
